## 3. Build sequence

### 1.1 `candor-limits`, `candor-time`, `candor-memlock`
- **Build:** `candor-limits` generated at build time from `tools/constants.json` (no network, deterministic, checked in or generated by a reviewed script) and exposing `pub const` values. `candor-time`: `SourceClock::today() -> EpochDay`, `StaffClock::now()`, `Monotonic`. It is the only crate allowed to call `SystemTime::now`. `candor-memlock` (the only `unsafe`-allow-listed OS crate): `lock_arena`, `dontdump`, `set_nondumpable`, plus Landlock/seccomp helpers via `rustix`/`landlock`/`seccompiler`.
- **Rules:** IMP-STD-004, IMP-STD-007, IMP-STD-023. SI-A-04, SI-A-05.3, SI-B-02, SI-B-03. 07 §12. ADR-010.
- **Pitfalls:** a literal duplicated in code drifts from the registry (SG-25). A "debug" constructor that returns exact time.
- **Verify:** ST-167 in-code literal scan. AT-040 (no sub-day type reachable from intake crates, compile test). Miri and Kani on `candor-memlock`. Test that `/proc/self/status` shows `Seccomp: 2` and `NoNewPrivs: 1` after `apply()`.

### 1.2 Primitive wrappers and RNG (T0)
- **Build:** `suite` (CANDOR-STD-1 only on the CE path; FIPS as a compile-time feature, never negotiated), `rand` (`getrandom` only, failure → error), `kem` (HPKE with X-Wing 0x647a via `hpke =0.14.1`; validated `from_bytes`), `aead` (ChaCha20-Poly1305 / XChaCha; nonce types private), `kdf` (HKDF-SHA-256 with `enum Label`), `sig` (Ed25519, keypair-only signing API), `hash` (SHA-256/BLAKE3), `passphrase` (EFF list per ADR-050(2), Argon2id m = 64 MiB, t = 3, p = 1), `secret` (zeroizing containers), `selftest` (startup KATs; ST-028).
- **Rules:** SL-R-003, SL-R-011, SL-R-012, SI-A-05, SI-A-06. 04 §4, §8, §10, §11. 27 §11.3 checklist. IMP-STD-006, IMP-STD-011.
- **Pitfalls:** INC-SL-06 / libolm (table-based AES timing) → only constant-time backends. INC-51 (Debian RNG) → no seeded PRNG. INC-61 ROCA (weak keygen) → KATs plus a weak-key check in `selftest`. RUSTSEC-2022-0093 (double-public-key oracle) → keypair-only signing. Nonce exposure (B-SL-25).
- **Verify:** ST-020/021/022 KATs (hash-pinned files). ST-023 Wycheproof (X25519 low-order, ChaCha20-Poly1305, Ed25519, ML-KEM invalid-ek). ST-026 dudect on tag verify and decapsulation failure vs success. ST-028 self-test. Label registry uniqueness and prefix-freeness.

### 1.3 Wire formats: Sealed Object, Recipient Slot Block, STREAM, padding, records (T0)
- **Build:** `object` (04 §13.1), `slots` (16 anonymous fixed-size slots in random order, no key IDs; dummy-slot derivation per ADR-050(1); full recipient-set re-derivation per ADR-050(3)), `stream` (64 KiB chunks, counter ‖ last-flag, release after authentication only), `padding` (ADR-011 buckets: `message_padding_bucket`, `attachment_padding_*`), `record` (04 §13.8), `header` (MAC binding, key commitment; 04 §8), `stanza` (case wraps). Typestate `Sealed`/`Opened`. Uniform `DecryptError::Invalid`.
- **Rules:** SL-R-003, SL-R-005, SL-R-011, SL-R-015. R8 §2.2 patterns 1–7. 04 §13.9 versioning (no downgrade). IMP-STD-004, IMP-STD-011, IMP-STD-012.
- **Pitfalls:** INC-62 / INC-SL-04 (ID re-resolution) → `Verified<T>`. INC-63 / INC-SL-05 (cross-protocol, compression) → labels and no compression. INC-65 Efail (plaintext released before authentication) → STREAM rule. INC-66 MEGA (malleable key material) → key commitment. INC-64 Telegram (non-standard construction) → no custom primitives. INC-14 Anom (hidden recipient) → ADR-050(3) re-derivation of all 16 slots.
- **Verify:** ST-024 proptests (round-trip, truncation, reorder, extra chunk, wrong last-flag, non-canonical encodings). ST-025 key commitment and context binding. ST-032 padding conformance. ST-040/041/042 fuzz (`fuzz_envelope_parse`, `fuzz_stream_decrypt`, `fuzz_hpke_open`). An invalid-envelope corpus where each entry has its expected error class (R8 §2.1 age/CCTV pattern). Kani on chunk-index, padding-bucket and length arithmetic. Property test: only slot k of 16 is substituted → rejected for every k (INC-SL-08).

### 1.4 Key-directory log format and verification library (T0)
- **Build:** `kd` module or crate: entry encodings (04 §14.2 type bytes), RFC 6962 Merkle hashing (leaf `0x00`, node `0x01`), signed-note checkpoints (04 §14.3), inclusion and consistency proofs, the continuity rules (04 §14.4), a `verify_snapshot(prev_high_water, snapshot) -> Result<Verified<Snapshot>>` that enforces the witness quorum (ADR-036(5)), the freshness bound `directory_snapshot_max_age` (ADR-047(4)) and the time-lock `effective_day` (ADR-036(2)), and the hidden-recipient check (04 §14.6).
- **Rules:** SL-R-003 (verified bytes only), IMP-STD-011. ADR-036, ADR-046, ADR-047(4).
- **Pitfalls:** INC-14 Anom / THR-046 (key substitution). INC-SL-04 (check, then use by ID). Split view and rollback (accepting a smaller tree). Signature over a non-canonical encoding.
- **Verify:** ST-033 key-directory verification. ST-046 `fuzz_key_directory`. ST-094 split view and rollback vectors. ST-149 rollback/freeze rejection. ST-151 witness cosignature enforcement. ST-172 freshness bound. Mutation testing on `verify_*`.

### 1.5 Formal model v1 (T0)
- **Build:** `protocol/` with Tamarin and/or ProVerif models of intake sealing (Tier W and Tier V), reply, follow-up and directory verification. The lemmas listed in 04 cover secrecy, authentication, no cross-protocol acceptance (INC-63) and no hidden recipient. CI job `formal-models`.
- **Rules:** RM-003, ST-030, R8 §1.4 (models are re-checked on every PR touching `protocol/` or `candor-core/src/proto*`). SL-R-004 (`security/proof-tcb.toml` lists the modelled versus unmodelled parts).
- **Verify:** all lemmas proved. Wire formats are frozen only after this (RM-003).

### 1.6 `candor-safefs` (T0)
- **Build:** `openat2` (`RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS`), `O_CREAT|O_EXCL`, content-addressed and random names, `RootPolicy` (Store, Staging, Export), fixed mtimes (`utimensat`), owner and mode checks on roots, validate-then-link via `O_TMPFILE`, and an allow-list archive reader (tar, tar.gz, zip) with 10 §10 limits checked before writing.
- **Rules:** ADR-027, SL-R-001, IMP-STD-010. 07 §10.
- **Pitfalls:** INC-101 / INC-SL-01 (write then check). INC-102 (gzip FNAME absolute path). INC-108 (symlink following). INC-107 (writes when disabled). RUSTSEC-2025-0168 (zip canonicalisation). The std `remove_dir_all` TOCTOU (CVE-2022-21658). The tar PAX-size parser differential (RUSTSEC-2026-0067/0068) (R9 §1.5).
- **Verify:** ST-005 lint (no `std::fs` with dynamic paths elsewhere). ST-048 `fuzz_safefs_names`. ST-049 `fuzz_archive`. ST-080 traversal corpus. ST-081 archive attacks. ST-086 symlink containment. An inotify test asserts that no inode appears outside the root on a hostile name. The non-root CI job covers the foreign-owner refusal.

### 1.7 `candor-log` (T1)
- **Build:** sealed event catalog (20 §5), `AuditField` trait with no impls for `String`, `&str`, `IpAddr`, `PathBuf`, `SystemTime` or raw integers, `Sensitive<T>` (no Debug/Display/Serialize), canonical CBOR envelope (20 §4), per-class hash chain and checkpoints (07 §5.9), verifier, k-threshold suppression for metrics (24 §TEL), and `audit/schema.yaml` as the single source with a CI drift check (LOG-014).
- **Rules:** IMP-STD-008. ADR-016, ADR-051(3). 20 §6.1 prohibited fields. SI-C-04 logging.
- **Pitfalls:** INC-60 (passwords in logs). INC-56 (HAR files: support artefacts carrying tokens). INC-03 (IP logging on demand: the absence of the capability is the control). Differencing across aggregate releases (THR-039).
- **Verify:** compile-fail tests (`tests/ui`). AUD-001/004 chain tamper suite. ST-051 `fuzz_audit_log_verify`. AT-003, AT-015, AT-067. The suppression differencing attacker test (AT-065/066).

### 1.8 `candor-source-ui` (T1; rendering library only)
- **Build:** askama templates with auto-escape and no `|safe`. No inline script or style. Locale bundles (Fluent). Response builder emitting the exact 11 §5.3 header set (CSP `default-src 'none'`, `script-src 'none'` in no-JS mode, `form-action 'self'`, `frame-ancestors 'none'`, `base-uri 'none'`, no `Server`/`Date` build info, `Cache-Control: no-store`). Size-class padding (P1 = 64 KiB, P2 = 128 KiB; a function of the request type, not the page; ADR-051(2)) applied **after** rendering, with no compression. A static-asset metadata strip at build time.
- **Rules:** SI-C-03, SI-C-06, SL-R-007. 11 §5.1–§5.4, §9. ADR-011, ADR-051(2). IMP-STD-005.
- **Pitfalls:** INC-117 (stored XSS through an escaping bypass flag). INC-118 / INC-SL-14 (headers declared but missing in production). INC-46 / INC-53 (third-party resources). INC-36 TorMoil (`file://` links). BREACH-style compression oracles.
- **Verify:** ST-072 XSS polyglot corpus through every template variable. ST-074 header golden test per route × locale. AT-046 size classes (every page × locale fits its class; a build-time test). AT-050/051/053/054 (Safest mode, no cookies beyond spec, no fingerprinting surfaces, caching). `csp-evaluator` with 0 findings ≥ Medium. `exiftool -all` on static assets returns empty.

### 1.9 Conformance, multi-arch and side-channel evidence
- **Build:** a differential harness (`hpke` vs a second implementation; portable vs SIMD backends). A CI matrix: x86_64-v1, x86_64-v3, aarch64 ± SHA3 extension, forced-portable. `security/proof-tcb.toml`. A dudect runner. A zeroization memory-scan test (debug build, canary key, scan after drop). A LoC budget (`tokei`): `candor-core` protocol logic ≤ 5k SLOC unless a Crypto Reviewer note says otherwise (R8 §1.8).
- **Rules:** SL-R-004, SL-R-012, SL-R-015. IMP-STD-016.
- **Verify:** ST-029 differential (10⁶ inputs per release). ST-026 (|t| < 4.5). ST-027 zeroization. All suites green on every arch.

### 1.10 Retroactive independent audit and format freeze
- **Build:** run the independent audit gate (IMPL-00 §13) separately for each crate already merged: `AUDIT-RM1-core.md`, `-safefs.md`, `-log.md`, `-source-ui.md`. Close findings. Then freeze format versions (RM-003).
- **Verify:** 0 open Critical/High. Internal crypto review sign-off recorded (38 RM-1 exit).

## 4. Component-specific threat checklist (auditor)

| # | Check | Where |
|---|---|---|
| A1 | Every secret type: no Clone/Debug(non-redacted)/Display/Serialize/PartialEq. Zeroized on all paths, including errors and early returns | `secret`, `passphrase`, `kem`, `stream` |
| A2 | No secret-dependent branch, index or early return. Comparisons use `subtle` | all T0 |
| A3 | No nonce parameter in the public API. Nonce uniqueness argument written in SPEC-NOTES | `aead`, `stream` |
| A4 | STREAM never yields unauthenticated bytes. A missing last-flag or extra chunk is rejected. Truncation at every chunk boundary is rejected | `stream` |
| A5 | Header MAC and key commitment bind every header field. Labels are unique and prefix-free. HPKE `info` is unique per role | `header`, `labels` |
| A6 | All 16 slots are re-derived and byte-compared (ADR-050(3)). Dummy slots are indistinguishable (same size, same derivation) | `slots` |
| A7 | Lengths: every `as` cast, `+`, `*` and `<<` on wire data is checked. Allocation only after a limit check | all parsers |
| A8 | Public key deserialization rejects low-order, non-canonical and invalid ML-KEM keys | `kem` |
| A9 | Directory: rejects older or smaller trees, missing witness quorum, stale snapshots and future `effective_day`. Returns `Verified` with exact bytes | `kd` |
| A10 | Suite and version: no runtime negotiation to a weaker suite. Unknown version → reject | `suite`, `object` |
| A11 | safefs: no path is built from input outside the API. Symlink and hardlink escapes, `..`, absolute paths, NUL, overlong and Unicode-dot names are refused **before** any write | `candor-safefs` |
| A12 | candor-log: no free-text path. No impl of `AuditField` for raw types. Canonical CBOR is strict. The chain verify detects every tamper class | `candor-log` |
| A13 | source-ui: no `|safe`, inline script or style, or third-party URL. Header set exact. Size class depends on request type only. No compression | `candor-source-ui` |
| A14 | Panics: no reachable panic from hostile input (fuzz evidence) | all |
| A15 | Dependencies: crypto set meets `candor-crypto-reviewed`. No duplicate primitives except ADR-051(1) | `Cargo.toml`, `supply-chain/` |

## 6. OPSEC checklist

| Metadata at risk | Prevention |
|---|---|
| Secret bytes in `Debug`, error text or panic messages | Redacted `Debug`, code-only errors, a canary `format!` test |
| Size of plaintext revealed by ciphertext length | ADR-011 buckets. Padding is applied before encryption and tested (ST-032, AT-044/045) |
| Recipient identity in the header | 16 anonymous slots, no key IDs, random order (A6) |
| Time in formats | No timestamps in the Sealed Object or slots. `EpochDay` only where 04 defines it |
| File mtimes and names on disk | safefs fixed mtimes and random or content names |
| Page identity revealed by response size | Size class depends on request type only (ADR-051(2)) |
| Static assets carrying author or tool metadata | Build-time strip plus exiftool check |
| Locale leaking via `Accept-Language` | Language from the URL path only (11 §5.5). Header ignored and never logged |

## 9. Residual risks and open issues

- `hpke =0.14.1` X-Wing and `ml-kem 0.3.2` are young implementations. Differential testing against a second implementation reduces the risk of a wrong result but not of side channels. dudect is statistical.
- The formal model covers the modelled protocol, not the Rust code (no hax/F\* extraction in CE). Spec-to-code divergence is caught only by vectors and review.
- Size-class padding hides content size but not the number of requests (THR-003/THR-047, handled in RM-2).
- Open: whether `kd` lives in `candor-core` or a sibling `candor-kd` crate (an ADR-031 licence question; Apache/MIT preferred for client reuse).
